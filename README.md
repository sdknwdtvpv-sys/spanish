# Lingua · 西班牙语学习应用

面向**中文母语者**的西班牙语学习应用，覆盖 **CEFR A1–C2 全等级**。
Capacitor 原生壳 + 纯前端 PWA，**无框架、无打包器**，全部语音**离线预生成**。

---

## 一、北极星

> **让中文母语者从零基础真正走到 C1/C2——用「可核验的严谨内容」+「不依赖网络的完整语音」，做到游戏化产品做不到的深度。**

### 为什么是这个

先说清楚**哪些是已验证的、哪些是判断**：

- ✅ **已验证**：本项目自身 A1–C2 六级都有实打实的内容（每级 20+ 单元、900+ 词），
  且 6653 个词条全部经过自动化审计
- 🔍 **判断（未做竞品调研）**：游戏化学习产品通常把重心放在早期留存，
  高级内容的投入产出比低。**我没有实际测量过任何竞品的内容深度**，
  这一条是基于常识的假设，不是结论——如果要写进对外材料，需要先调研

Lingua 的答案是三件具体的事：

| 支柱 | 具体到什么程度 | 为什么是北极星而不是"想做得好" |
|---|---|---|
| **内容严谨** | 6653 个词条全部经脚本审计（P0/P1/P2 归零）；而**语言本身的正确性/地道性/讲解准确性我无法判定**，已单列成复核清单交母语者（见 `REVIEW-CHECKLIST.md`） | 因为**教错比教少更糟**——学习者会把错误内化 |
| **完整语音** | 6362 条音频离线打包，不依赖设备引擎、不依赖网络 | 因为**发音和学习体验不能受制于用户手机装没装 TTS** |
| **全等级覆盖** | A1–C2 每级都补齐到 20+ 单元、900+ 词，不是"高级只有几个单元" | 因为**"能学到 C2"是产品的存在理由**，不是卖点包装 |

### 我们明确**不**优化的东西

写下来避免后续偏离：

- ❌ **日活 / 留存 / 打卡** —— 不做推送催学、不做断签惩罚
- ❌ **社交裂变** —— 社区是静态展示，不做排行榜和好友 PK
- ❌ **广告变现** —— 数据只存在本机
- ❌ **内容数量竞赛** —— 宁可补 100 个经得起审的词，不塞 1000 个没查过的

### 怎么判断有没有偏离

三个可检验的问题：

1. 新增内容**是否经得起"逐个词条核验"**？（还是只加了个数字）
2. 核心功能**是否在断网、无 TTS 引擎的真机上可用**？
3. 高级学习者（B2 以上）**是否还能继续往下学**？

## 三、快速开始

### 环境要求

- **Node.js 22+**（实测 v22.22.2）
- 浏览器：Chrome 或 `chrome-headless-shell`（跑回归测试用）
- 打包 Android 另需 JDK 17 + Android SDK（见下）

### 本地运行

```bash
cd spanish-app
npm install
npm run serve        # 默认 4173，可用 PORT=xxxx 覆盖
# 浏览器打开 http://localhost:4173
```

`scripts/serve.mjs` 绑定 `0.0.0.0`，所以**同一局域网的手机可以直接访问**，
方便真机调试而不必打包。

### 打包 Android

工具链**刻意放在工作区内**（`~/` 会被环境清理，本项目踩过这个坑，
JDK 与 Android SDK 都曾消失导致构建失败）：

| 工具 | 路径 |
|---|---|
| JDK 17 | `.jdk-download/jdk-17.0.20.1+1/Contents/Home` |
| Android SDK | `.android-sdk` |
| Gradle 缓存 | `.gradle-home` |

三者都在 `.gitignore` 里（体积大、可重建）。

```bash
cd spanish-app
bash tools/build-android.sh
# 产物：../lingua-debug.apk
```

该脚本会**强制 `cap sync`** 并**解包校验 `courses.js` 的 MD5 与源码一致**——
因为曾经出现过「构建成功但 APK 里是旧内容」的情况（详见第七节）。

安装到真机：

```bash
adb install -r -t lingua-debug.apk
```

## 五、常用命令

```bash
npm run audit          # 内容审计 + 缺口审计 + 数据完整性（三合一，最常用）
npm run audit:content  # 六层内容审计
npm run audit:gaps     # 语法覆盖 / 成就 / 社区帖 / 搭配 缺口
npm run check:data     # 数据完整性（防回归，15 项）
npm run check:fresh    # 资源新鲜度（www 与 Android 资源是否为当前源码）

npm test               # 三层回归一次跑完（含新鲜度前置检查）
npm run test:core      # 50 项核心回归
npm run test:content   # 逐条渲染全部单元/精读/语法主题
npm run test:rapid     # 9 项连点稳定性

npm run sync:web       # 根目录 → www/
npm run build:android  # 同步 + cap sync + gradle（推荐用 tools/build-android.sh）
```

### 跑浏览器回归

需要一个无头 Chrome 与静态服务：

```bash
cd spanish-app
npm run serve &                       # 终端 A
CDP_PORT=9411 bash tools/test-env.sh  # 终端 B（启动 headless Chrome）
CDP_PORT=9411 npm test
```

### 跑真机测试

```bash
adb install -r -t lingua-debug.apk
adb shell monkey -p com.lingua.spanish -c android.intent.category.LAUNCHER 1
adb shell pidof com.lingua.spanish                       # 取 pid
adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>
cd spanish-app && CDP_PORT=9222 node tools/device-smoke.mjs
```

**为什么走 DevTools 而不是 `adb input tap`**：坐标点击在真机上不可靠——
键盘弹出后布局上移，后续点击会落到**设备上的其他应用**上（本项目实际发生过）。
走 DevTools 可以直接读写页面，不触碰屏幕。

## 六、验证体系

### 三个审计脚本 = 内容的"编译检查"

| 脚本 | 检查什么 | 覆盖 |
|---|---|---|
| `audit-content.mjs` | 结构完整性、交叉引用、内容严谨性、教学一致性、CEFR 错配、待复核清单 | 六层 |
| `audit-gaps.mjs` | 语法点是否都有练习题、成就/社区/搭配的覆盖缺口 | 四层 |
| `check-data.mjs` | 字段缺失、空值、重复、孤立逗号、答案唯一性 | 24 项 |

**当前状态：P0 / P1 / P2 全部为 0。**

### 三层回归 = 行为的"编译检查"

| 脚本 | 覆盖 |
|---|---|
| `regress-core.mjs` | **50 项断言**（源码 42 个 check 调用，部分在循环内展开）：冷启动、登录、五条路由、单词卡与 SRS、四种学习模式、精读、搭配、等级过滤、备份导入导出、本地音频链路 |
| `regress-content.mjs` | **逐条打开** 125 个单元 + 63 篇精读 + 124 个语法主题，检查渲染与异常 |
| `regress-rapid-click.mjs` | 同步突发点击，验证只计一次分 |

### 一个必要的约束

**浏览器回归跑在 `www/` 上，APK 打包 `android/.../assets/public/`——
只要漏掉一步同步，测试和构建都会"成功"，但验的是旧内容。**

所以 `scripts/assert-fresh.mjs` 对四组副本（www 与 Android 各自的资源与代码）做 MD5 比对，不一致就**以退出码 9 中止**，
并已接进三层回归与 `npm test`。

## 七、几个关键决策（都是踩坑后定下的）

### 1. 语音走「构建时预生成」而非「运行时合成」

真机校验发现三条运行时路径**全部不可用**：

| 路径 | 真机实测 |
|---|---|
| Web Speech API | Android WebView **没有这个 API** |
| Google `translate_tts` 兜底 | WebView 里被拦，`<audio>` 连 HTTP 头都读不到 |
| 系统 `TextToSpeech` | 设备上引擎不可用（`TtsService enabled=0`），初始化返回 `ERROR` |

三者共用同一个 `speakWord()`，而数据里**没有任何音频文件**——
所以没有可用引擎时，**发音 / 听力 / 口语三个功能整体失效**。

**决策**：用 macOS `say` + `afconvert` 离线合成 **6362 条音频**打包进 App。
不依赖引擎、不依赖网络，装到任何设备都能响。
原生 TTS 保留为次优先路径（用户装了引擎则音色更好）。

### 2. SRS 用 `单元ID:单词` 作键，而非单词本身

`reunión` 在 A2-u1 是"聚会"、在 A2-u7 是"会议"。用单词本身作键会导致
**两个词的复习记录互相覆盖**——学完"聚会"打开"会议"，系统显示"你已经会了"。
老用户数据会自动迁移（v1 → v2）。

### 3. 宁可保留"我不确定"，也不猜

审计无法判定的项目（西语地道性、语法讲解的学术准确性、中文翻译的信达雅）
**不硬判**，列入 `REVIEW-CHECKLIST.md` 交母语者复核。
把"可自动判定的"和"需人判断的"分开，是这个项目的方法论核心。

## 九、已知限制

诚实列出，避免误解项目状态：

**功能层面**
- **没有后端**：登录是纯前端 localStorage 模拟，多设备无法同步。这是刻意的架构决策（保留给产品决策），不是未完成
- **社区是静态数据**：8 条预置帖子，无真实互动
- **无音频录制比对**：口语跟读只提供标准音，不评分

**验证层面**
- **平板 / 横屏从未验证**：所有真机测试都在 394×853 竖屏完成
- **iOS 从未构建**：工程存在但未编译过
- **长时使用未测**：只测了单次会话，30 分钟以上的内存/发热未知
- **离线场景未测**：飞行模式下 Service Worker 的缓存行为

**内容层面**
- **语言正确性未经母语者复核**：脚本能保证结构与一致性，但「西语是否地道、语法讲解是否讲对、中文翻译是否准确」需要人工判断，清单见 `REVIEW-CHECKLIST.md`
- **发音为合成音**：`Eddy`（es_ES）机器音，非真人录音
- **搭配库高级部分偏书面**：收录了大量书面惯用语（`de motu proprio` 等），
  与初学者日常用语不是同一语域

## 十、一条给后续开发者的提醒

这个项目 90% 的工作量在**内容**，而不是代码。代码只有 3400 行，
但内容是 6653 个词条、752 道题、63 篇精读——**每一条都需要逐条核验**。

所以最重要的工程实践是：**任何内容变更都必须伴随脚本校验**。
本项目在扩充过程中被自动审计抓到 **16 次**自己引入的问题
（语法点重名 5 次、词条重复 3 次、共用例句 3 次、例句未含词形 1 次、
别名关键词不匹配 4 次），**没有一次是人工看出来的**。
